# Thesis Proposal

## 1. Попередня робоча назва проєкту

**Українською:** «Цукровий Компаньйон» — гейміфікована система дистанційного моніторингу та підтримки терапевтичної дисципліни дітей з цукровим діабетом I типу

**English:** *GlucoBuddy — a gamified remote-monitoring and adherence-support system for pediatric Type 1 diabetes management*

## 2. Актуальність та проблематика

Терапія цукрового діабету I типу в дитячому віці вимагає регулярного, дисциплінованого виконання рутинних медичних дій: вимірювання рівня глюкози, підрахунку хлібних одиниць (ХО) та своєчасного введення інсуліну. Складність проблеми полягає у низькій комплаєнтності (adherence) серед дітей та підлітків: рутинні медичні дії сприймаються як примусові й стресові, що призводить до пропусків вимірювань, недостовірного самоконтролю та підвищеного ризику гострих і хронічних ускладнень. Водночас батьки та лікуючий лікар потребують достовірних, структурованих та історично простежуваних даних для коригування терапії.

Інженерна проблема таким чином є двоскладовою: (1) сформувати мотиваційний механізм для регулярного внесення медичних показників дитиною через ігрову взаємодію, не спотворюючи при цьому достовірність даних; (2) забезпечити надійне, безпечне та масштабоване зберігання й аналітичну обробку чутливих медичних даних у реальному часі для батьківського та лікарського контурів.

## 3. Сформована ідея продукту

Кросплатформний мобільний застосунок з подієво-керованою (Event-Driven) мікросервісною бекенд-архітектурою для менеджменту терапевтичної дисципліни дітей з цукровим діабетом I типу. Клієнтська частина реалізує дві ізольовані площини взаємодії (BFF-патерн): ігровий інтерфейс дитини та аналітичну панель батьків/лікаря. Стан «віртуального компаньйона» на клієнті є похідною проєкцією (read-model) від потоку медичних подій, що надходять до бекенду, що зумовлює застосування патерну CQRS для розділення запису показників і формування аналітичних read-моделей.

## 4. Детальний опис функціоналу (Core Features)

1. **Гейміфікована форма введення показників** — спрощений UI для фіксації рівня глюкози, хлібних одиниць та інсуліну, що генерує подію в системі (event) без додаткових ручних синхронізацій.
2. **Інтерактивний дашборд-компаньйон** — read-model, що відображає стан персонажа (анімації активності/спокою/тривоги) як реакцію на потік медичних подій у діапазоні цільових значень.
3. **Подієво-керована система прогресії та нагород (XP/Achievements)** — асинхронний сервіс нарахування досвіду та розблокування косметичних предметів на основі безперервності дотримання режиму (streak-логіка).
4. **Батьківський/лікарський аналітичний модуль** — окремий захищений BFF-контур з агрегованими графіками, трендами та експортом звітів на основі часових рядів показників.
5. **Сервіс проактивних нагадувань (Notification Service)** — асинхронна розсилка push-повідомлень від імені персонажа за розкладом та за відхиленням показників від норми.
6. **Розмежування доступу за ролями (RBAC/ABAC)** — автентифікація та авторизація для трьох ролей (дитина, батько/опікун, лікар) з різними рівнями видимості медичних даних.
7. **Контур захисту медичних даних** — шифрування даних у стані спокою та під час передавання, журналювання доступу (audit log) відповідно до вимог захисту персональних медичних даних (аналог GDPR).

## 5. Попередній інструментарій та технологічний стек

| Категорія | Технології |
|---|---|
| Мови програмування | TypeScript, Go |
| Frontend / Mobile | React Native, TypeScript, Redux Toolkit |
| Backend | Node.js (NestJS) — сервіси прогресії та нотифікацій; Go (Fiber) — сервіс прийому медичних подій (висока пропускна здатність) |
| Архітектурні патерни | Microservices, Event-Driven Architecture, CQRS, BFF (Backend for Frontend) |
| Брокер повідомлень | Apache Kafka — потік медичних подій та асинхронна обробка нагадувань |
| Бази даних | PostgreSQL (транзакційні дані користувачів), TimescaleDB (часові ряди показників глюкози/ХО), Redis (кешування read-моделі стану компаньйона) |
| Безпека | OAuth2 / OpenID Connect, JWT, шифрування AES-256, Trivy (сканування контейнерів у CI) |
| DevOps / CI-CD | Docker, Kubernetes, GitHub Actions, ArgoCD (GitOps, Canary/Blue-Green розгортання) |
| Observability | OpenTelemetry, Prometheus, Grafana |
| Документація | Swagger / OpenAPI, Docusaurus (Documentation as Code) |
| Дизайн | Figma (High-Fidelity прототипи, Auto Layout) |
